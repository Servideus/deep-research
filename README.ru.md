# deep-research

Форк [oh-rid/deep-research](https://github.com/oh-rid/deep-research), плагина Claude Code для исследования веб-источников с независимой проверкой несколькими семействами моделей. Основной исследователь сопоставляет результаты и проверяет первоисточники до включения утверждений в отчёт.

## Статус форка

README описывает исторический снимок upstream v0.2.0 и изменения форка от 26.07.2026. Имена моделей и настройки CLI относятся к этому снимку; совместимость с установленными сегодня инструментами нужно проверить. Обновление документации не подтверждает текущую работу всей цепочки.

Изменения форка:

| Изменение | Назначение |
|---|---|
| Закреплённые модели | `claude-opus-5`, `gemini-3.6-flash-high` через agy и `gpt-5.6-sol` через Codex в исторической конфигурации |
| Пустой рабочий каталог для CLI | Снизить риск чтения и передачи файлов проекта внешней модели; режим read-only сам по себе не запрещает чтение |
| Europe PMC | Получать идентификаторы литературы из базы через REST и сверять ссылки моделей |
| Контракт цитирования GPT | Требовать отрывок рядом с цитатой и самостоятельную предварительную проверку |
| Gemini как источник направлений поиска | Получать под-вопросы, словарь поиска, ожидаемые противоречия и пробелы без права добавлять непроверенные цитаты |

В agy-промпты добавлен запрет shell-вызовов: в наблюдавшемся headless sandbox-запуске отклонённая попытка такого вызова приводила к пустому результату.

## Установка

Это локальный плагин Claude Code. Исходная схема размещения:

```sh
mkdir -p ~/.claude/plugins/local/plugins
cd ~/.claude/plugins/local/plugins
git clone https://github.com/Servideus/deep-research.git
```

Включите локальный плагин в своей версии Claude Code и перезапустите или перезагрузите плагины. Проверьте доступность `/research`. Способ регистрации плагинов зависит от установленной версии; одно клонирование не является проверкой установки.

Для полной цепочки нужны `agy` (Antigravity CLI с доступом к Gemini) и OpenAI Codex CLI с веб-поиском. Проверьте реальные `--help` и настройки своих версий. Исторические имена моделей и конфигурация из английского README не являются рекомендацией для текущего выпуска CLI.

Если CLI отсутствует или недоступен, исследователь должен отметить пропуск или работу с меньшим числом проверяющих, а не выдавать её за полную проверку. Запросы используют доступ и лимиты ваших подписок/API.

## Использование

```text
/research Каков текущий научный консенсус по выбранному вопросу?
/research О какой стране идёт речь в указанной исследовательской записке?
```

Команда запускает исследователя в отдельном worktree. Результаты внешнего поиска оборачиваются как недоверенные данные. Итог содержит краткий вывод, пронумерованные находки со ссылками, карту уверенности, отклонённые утверждения, открытые вопросы и статус каждого проверяющего. Отдельно отмечаются выводы, где есть согласие моделей без найденного первоисточника, и полезность каждого потока исследования.

## Цикл исследования

1. Проверить CLI фактическими командами, создать уникальный `RUN_ID` и запустить внешние потоки из пустого временного каталога.
2. Разделить вопрос на под-вопросы и выполнить собственный поиск Claude.
3. Записать собственные выводы до чтения ответов других моделей.
4. Сопоставить совпадения, уникальные находки и противоречия.
5. Проверить ссылки и подтверждающие отрывки, разрешить расхождения и составить отчёт.

## Проверка и защита

Вес доказательства важнее числа согласившихся моделей. Ответ HTTP 2xx подтверждает доступность URL, но не подтверждает, что страница содержит нужное утверждение: требуется проверка соответствующего отрывка.

| Риск | Предусмотренная мера |
|---|---|
| Совпадающие ошибки моделей | Разные семейства моделей и проверка первоисточников |
| Выдуманные цитаты | Проверка URL и совпадения отрывка с содержимым |
| Несуществующий флаг CLI | Проверка через `--help` или документацию поставщика |
| Инструкции в веб-странице | Внешний текст считается данными; команды из него не исполняются |
| Доступ к файлам проекта | Worktree и отдельный пустой рабочий каталог CLI |
| Конфликт временных файлов | Уникальный `RUN_ID` в именах |

Эти меры снижают риски, но не гарантируют истинность всех выводов или полной изоляции на любой платформе. Исследователь должен проверять доступные механизмы sandbox в конкретном окружении.

## Структура

```text

```

Инструкции исследователя находятся в `agents/researcher.md`, команда — в `commands/research/COMMAND.md`. Английский README сохраняет подробную историческую архитектуру и таблицы сравнений.

## Ограничения

Если точного числа или первоисточника нет в доступной сети, вопрос должен остаться открытым. Лимиты Gemini могут привести к повтору или замене потока собственным поиском; это отмечается как `SELF_SUBSTITUTE`. Без веб-поиска Codex полная цепочка не работает. Временные файлы имеют уникальные имена, но не заменяют последующую уборку каталога.

Исторический upstream-отчёт заявлял end-to-end проверку v0.2.0 от 22.05.2026; это отчёт прошлого запуска, а не свежая проверка этой версии.

## Источники подхода и лицензия

В README и инструкциях сохранены ссылки на [Shared Imagination](https://arxiv.org/abs/2407.16604), [Chain-of-Verification](https://arxiv.org/abs/2309.11495), [исследование выдуманных цитат](https://arxiv.org/abs/2602.05930) и [работу о согласии моделей](https://arxiv.org/abs/2510.19507). Приведённые выводы требуют сверки с самими работами; доступность URL не равна проверке содержания.
